# Development

## Prerequisites

- Node.js 24
- pnpm, through Corepack. The version is pinned by the `packageManager`
  field in `package.json`; run `corepack enable` once and Corepack provides
  the matching pnpm.

## Running the app

```sh
make dev
```

This installs nothing; run `make deps` first on a fresh checkout. The dev
server listens on http://localhost:5173 and refuses to start if that port is
taken, because sign-in redirects back to that exact address.

Sign-in needs the session API server running on http://localhost:8787 (set
in `packages/apps/web/.env.development`) and the GitHub App's client id.
Put the client id in `packages/apps/web/.env.local`, which is not committed:

```sh
VITE_GITHUB_CLIENT_ID=<the GitHub App client id>
```

The GitHub App must list `http://localhost:5173/callback` as one of its
callback URLs; GitHub refuses to redirect anywhere else.

`packages/apps/web/.env.example` lists every variable the app reads.

## Running without the session API

```sh
VITE_API_MOCK=1 make dev
```

With `VITE_API_MOCK=1`, the app starts [Mock Service Worker](https://mswjs.io/)
in the browser and answers the session API and GitHub's `GET /user` from the
handlers in `packages/testing/api-mocks`, the same ones the tests use.
"Sign in with GitHub" skips the GitHub authorize page and returns straight to
the callback with a mock code, so sign-in completes without leaving
localhost and without a client id. The mock session survives a reload in the
same tab, as the refresh cookie would, until "Sign out".

The worker script is `packages/apps/web/public/mockServiceWorker.js`,
generated by `msw init`. After upgrading `msw`, regenerate it into the
directory listed under `msw.workerDirectory` in
`packages/apps/web/package.json`:

```sh
pnpm --filter @yagura/web exec msw init
```

The mocks are loaded only in this mode and are not part of the production
bundle.

## Checking changes

```sh
make check
```

This installs dependencies from the lockfile, then runs the build, type
check, tests, lint, format check, and dependency rules across the workspace.
It is the same gate CI runs on every pull request. Run `pnpm format` to fix
formatting.

## Workspace layout

Packages live at `packages/<layer>/<name>`. The layers and what each may
import from the rest of the workspace:

| Layer     | May import                  |
| --------- | --------------------------- |
| `apps`    | anything                    |
| `ui`      | `libs`                      |
| `gateway` | `domain`, `libs`            |
| `domain`  | nothing                     |
| `testing` | `domain`, `gateway`, `libs` |
| `libs`    | nothing                     |

No package imports `apps`, and circular imports are forbidden. The rules are
enforced by dependency-cruiser (`pnpm depcruise`, configured in
`.dependency-cruiser.cjs`).
